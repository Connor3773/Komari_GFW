# 被墙检测

Komari 的服务器被墙检测插件。基于已有 Agent 的 TCP 探测，结合大陆与非大陆目标判断连通性异常，通过系统通知渠道发送疑似被墙及恢复通知，并提供管理总览。

适用于 **Komari 1.6.1**，无需修改 Komari 核心或 Agent，也无需在受检服务器上额外安装脚本。

> “疑似被墙”是 TCP 连通性推断，不是封锁原因的确证。路由、DNS、目标服务及防火墙故障也可能影响结果。

## 核心功能

- **多目标检测**：自定义 3 个大陆目标和 2 个非大陆目标，支持域名、IPv4、IPv6 与端口。
- **按需监测**：自行选择受检服务器，支持搜索；新加入的服务器不会自动开启检测。
- **双向严格模式**：选择一个或多个境内探针，主动检测受检服务器的指定端口，双向均不通才判定异常，全部恢复才解除。
- **告警与恢复通知**：复用 Komari 系统通知渠道，连续多轮确认后通知，避免短时抖动和重复告警。
- **IP 脱敏**：通知和总览可隐藏 IPv4 后两段，IPv6 隐藏后半部分。
- **管理总览**：在“插件功能 / 被墙检测总览”查看服务器状态、各方向结果和最近事件；配置位于统一的“插件配置”页面。

## 检测规则

- **反向**：受检服务器主动连接 3 个大陆目标。
- **非大陆对照**：受检服务器主动连接 2 个非大陆目标。
- **正向**：严格模式下，选定的境内探针主动连接受检服务器的测试端口。

基础模式在大陆 0/3、非大陆至少 1/2 成功时连续确认告警；可改为非大陆必须 2/2 成功。解除要求 5 个主动探测目标全部成功。严格模式额外要求全部正向探针失败才告警、全部正向探针成功才解除。

默认每 60 秒探测，告警和恢复均连续确认 3 轮。缺失、离线、过期或错位样本不算失败，也不能解除告警；首次正常不发恢复通知，全部失败不判为被墙。新服务器不会自动加入。

通知标题为“服务器疑似被墙”和“服务器解除被墙状态”，包含服务器名、IP、状态和各方向结果。默认隐藏 IPv4 后两段，如 `203.0.*.*`；IPv6 隐藏后半部分。脱敏作用于通知和插件总览。

## 安装配置

1. 备份 Komari 数据，确认服务端为 **1.6.1**。
2. 从 [Releases](https://github.com/Connor3773/Komari_GFW/releases/latest) 下载 `komari-gfw-0.1.2.zip` 和 `SHA256SUMS`，核对 SHA-256 后在插件管理上传 ZIP，并批准声明的权限。不要使用 GitHub 自动生成的 Source code 压缩包。
3. 启用插件，打开“插件配置”，选择“被墙检测”。首次安装监测关闭。
4. 修改目标、选择受检服务器。严格模式另选境内正向探针，并为每台受检服务器设置实际开放的测试端口。
5. 在系统中配置通知渠道，模板包含 `{{message}}`，先发送测试通知。
6. 开启监测，使用表单内的“保存配置”，在“插件功能 / 被墙检测总览”查看结果。

配置和总览仅管理员可见，配置入口为 `/admin/plugins/config?short=komari-gfw`。境内探针可按名称、分组或显示 IP 搜索；筛选不改变已选项目。

从 0.1.0 / 0.1.1 升级时直接覆盖上传，不要先卸载。内部 ID `komari-gfw`、任务标识和状态格式保留，已有配置无需重填。

### 默认目标

```text
大陆电信  gd-ct-v4.ip.zstaticcdn.com:80
大陆联通  gd-cu-v4.ip.zstaticcdn.com:80
大陆移动  gd-cm-v4.ip.zstaticcdn.com:80
非大陆    1.1.1.1:443
非大陆    9.9.9.9:443
```

支持 `域名:端口`、`IPv4:端口`、`[IPv6]:端口`，不接受 URL、路径或凭据。域名由 Agent 本地解析；默认大陆目标同处广东，不能代表所有地区。仅使用获准连接的目标，按需增加地域独立性。

正向测试地址留空时使用 Komari 登记的 IPv4，无 IPv4 时使用 IPv6，也可自定义。插件不会开放端口或修改防火墙；境内探针需要独立、稳定的控制连接，不能探测自己。登记 IP 不一定等于实际出站 IP，混合地址族结果不能证明某个 IP 已解封。

## 权限与数据

系统 RPC 用于管理专属 TCP 任务、读取检测结果、发送通知和定向清理历史；路由权限用于提供管理员配置和总览接口；Node 兼容模块用于本地状态存储及摘要计算。插件不执行远程命令，不修改服务器防火墙。

- 不建立延迟历史副本：每个目标只持久化最新值、去重游标及必要告警状态。
- 已处理事件仅保留 7 天、最多 100 条；有效待发通知额外保留最多 24 小时。历史到期不会解除仍在持续的告警。
- 每小时通过宿主官方数据库 RPC，精确清理本插件任务超过 1 小时的**已结束聚合桶**。保留近期和仍在聚合的数据，不修改全局保留策略，不清理其它任务。批量删除有上限，大量旧数据可能分多轮清理。
- 不删除指标定义或共享字典、不执行全库 VACUUM。清理释放的页可复用，数据库文件不一定立即缩小。接口或表结构不兼容时停止清理并显示提示，检测与告警继续运行。
- 活跃监测配置移除服务器或关闭严格模式时，自动删除已不需要的专属任务及其历史。仅暂停监测时保留任务，便于恢复。

卸载前先保存关闭监测，按需使用“清理插件任务”，再禁用或卸载。宿主异常退出或强制删除插件可能跳过清理；人工处理时按 `[Komari GFW:` 所有权前缀核对，勿删其它任务。

## 开发与验证

需要 Node.js 24+；运行插件的 Komari 服务器无需安装 Node.js。

```sh
npm ci
npm run check
npm run audit:public
```

构建输出 `dist/komari-gfw-0.1.2.zip` 和 `dist/SHA256SUMS`。安装包仅包含 manifest、运行脚本、4 个页面资源和 MIT 许可证，不包含开发文档、测试、依赖或本地数据。

## 隐私

提交问题或贡献代码时，不要包含真实服务器清单、凭据、通知秘密、Cookie、数据库、运行状态、原始日志或相关截图。默认公网目标与保留地址测试数据可以提交。

`.gitignore` 和 `audit:public` 只是基础检查，提交前仍需人工检查敏感信息。CI 不使用生产凭据、不自动部署。

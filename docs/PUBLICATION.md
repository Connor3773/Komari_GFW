# 公开前检查

仓库当前保持私有。未来改为公开必须由仓库所有者明确执行或授权，不随开发和推送自动切换。

## 可以提交

- 插件源码、锁定的开发依赖、通用说明和自动化测试。
- 用户指定的公开默认 TCP 目标。
- 使用保留地址和合成服务器的测试数据，不含用户实际部署信息。

## 不得提交

- 真实服务器清单、节点名/地址、Client Token、API Key、登录 Cookie。
- 通知渠道秘密、机器人 token、邮箱密码、SSH 私钥。
- `.env*`、`komari.local.json`、数据库、状态文件、原始日志和本地测试目录。
- 包含上述信息的截图、备份、崩溃输出和打包附件。

`.gitignore` 与 `npm run audit:public` 提供基础检查，但无法识别所有无特征秘密。提交前仍需人工检查 diff，公开前还需检查整个 Git 历史。若秘密曾进入历史，应先撤销/轮换，再处理历史，不能只删当前文件。

## 发布门槛

1. 确认开源许可证和版权归属。目前尚未选择许可证，不声称已授予开源许可。
2. 确认测试记录区分单元测试、隔离宿主测试与生产验证。
3. 从干净提交重建 ZIP，核对内容白名单和 SHA-256。
4. 确认没有测试凭据、数据库或运行态数据进入源码和构建产物。
5. 明确“疑似被墙”的推断性质，以及 DNS、端口服务和多探针限制。

自动化只读取仓库并运行测试，GitHub Actions 未配置生产环境秘密或自动部署。

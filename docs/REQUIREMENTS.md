# 需求与验收

基线日期：2026-11-02。目标宿主：Komari 1.6.1。

## 已确认需求

1. 由被监测服务器的 Agent 主动发起 TCP 连接，不是外部探针对服务器入站端口检测。
2. 全局维护 5 个探测目标，固定 3 个大陆、2 个非大陆；名称和地址可自定义。
3. 地址支持域名或 IP 加端口。IPv6 字面量必须使用方括号。域名由 Agent 所在服务器解析。
4. 可选择需要检测的服务器，不自动将新增服务器加入检测范围。
5. 大陆全部探测失败，而非大陆可达时发送疑似被墙通知。
6. 先前告警的服务器在 5 个目标全部恢复可达后，发送解除通知。
7. 消息至少包含服务器名称、IP、被墙状态；可配置隐藏 IPv4 后两段。
8. 通知沿用 Komari 系统通知设置，不要求用户再次填写通知凭据。
9. 后台“插件功能”中有总览页，包含状态统计、逐服务器探测矩阵、最后检测时间和事件记录。

## 默认策略

- 探测间隔为 60 秒，可配置；首版限制为 30 至 300 秒。
- 告警连续确认 3 个有效周期，恢复连续确认 3 个有效周期；均允许 1 至 10。
- 非大陆至少 1/2 成功即可支持告警判断，可改为必须 2/2 成功。
- 默认开启 IP 脱敏。IPv4 后两段隐藏，IPv6 展示隐藏后半部分；不暴露服务器 token。
- 安装后监测默认关闭、服务器未选择、目标为空，避免未配置即探测第三方。
- 仅在状态变化时通知；首次获得正常状态不发恢复通知。
- 不将缺失、陈旧、重复、异步错位的数据计入连续确认。

## 状态语义

探测健康与告警状态分别存储。健康状态可为初始化、正常、疑似被墙条件、部分异常、全部失败、数据不足或已暂停。

- 全部失败不等于被墙，不发送被墙通知。
- 离线或缺少上报不等于 TCP 连接失败，不自动解除已有告警。
- 仅大陆部分恢复不解除；已触发的告警持续到完整恢复条件满足。
- 配置目标、间隔或服务器选择发生变化时重置样本计数和采样起点，保留仍被监测服务器的未解除事件。
- 对同一条采样重复读取不增加连续次数；数据中断打断连续确认。
- 插件重启不重发已成功发送的历史事件；存在网络投递不确定性时不能承诺第三方渠道严格 exactly-once。

## 地址和隐私边界

- 域名可能解析到多个 IP 或不同地址族，Agent 上报不包含实际连接的目标 IP 或源 IP。因此域名模式结论限于这些 TCP 目标的连通性，不证明某个 IPv4 或 IPv6 已被封锁。
- 若需要 IPv4 特定判断，应使用固定 IPv4 目标；不得将 IPv4/IPv6 混合结果宣传成某一个 IP 的准确解封证据。
- 通知中的 IP 是 Komari 登记的服务器 IP，不保证等于 NAT、多网卡或代理环境中的实际出站 IP。
- 不自动选择公共目标，不调用第三方封锁检测服务，不进行端口扫描。
- 总览及配置均要求管理员身份，不做公开状态页。

## 验收标准

1. 配置合法的 5 个目标和服务器后，仅所选服务器承担本插件任务。
2. 连续 3 次大陆 0/3、非大陆至少 1/2 时仅生成一次告警；重复轮询不重复计数或发信。
3. 已告警后大陆部分恢复、全部失败或缺失结果均不能解除；连续 3 次 5/5 才解除一次。
4. 总览能区分当前健康、告警仍未解除、等待确认和数据过期。
5. 脱敏开启时，通知正文、事件对象和插件总览不包含未脱敏的服务器 IP 或 token。
6. 配置保存可验证地址和数量；避免重复目标和无效端口。
7. 禁用监测能暂停本插件任务；清理仅涉及本插件拥有的任务，不修改用户既有任务。
8. 插件 ZIP 可在 1.6.1 上安装、启用、展示页面、保存配置和读取结果。
9. 系统通知未开启、未选择渠道或模板缺少正文时，明确显示不可发送原因，不假报投递成功。
